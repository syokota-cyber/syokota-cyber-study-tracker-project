## 🎯 開発プロセス概要

### 段階的開発・確認の原則
**テスト環境での動作確認を経てから本番環境にデプロイする**ことを基本原則とします。

### 開発環境の構成
```
開発環境: ローカル開発 → テスト環境 → 本番環境
├── ローカル開発: http://localhost:8000 (API), http://localhost:5173 (フロントエンド)
├── テスト環境: AWS Lambda (dev stage)
└── 本番環境: AWS Lambda (prod stage) + CloudFront + S3
```

---

## 🔄 開発フロー

### 1. ローカル開発フェーズ

#### 1.1 機能実装
```bash
# ローカル環境での開発
cd study-tracker-project

# バックエンド開発
cd src
python -m uvicorn api.main:app --reload --host 127.0.0.1 --port 8000

# フロントエンド開発
cd study-tracker-frontend
npm run dev
```

#### 1.2 ローカルテスト
- [ ] バックエンドAPIの動作確認
- [ ] フロントエンドの動作確認
- [ ] 統合テストの実行
- [ ] エラーハンドリングの確認

#### 1.3 ローカル確認完了条件
- ✅ すべての機能が正常に動作
- ✅ エラーが発生しない
- ✅ テストが通る
- ✅ ユーザビリティが確認済み

### 2. テスト環境デプロイフェーズ

#### 2.1 テスト環境へのデプロイ
```bash
# バックエンド（Lambda）のテスト環境デプロイ
serverless deploy --stage dev

# フロントエンドのテスト環境ビルド
cd study-tracker-frontend
npm run build
```

#### 2.2 テスト環境での動作確認
**⚠️ 重要: テスト環境での確認を必ず行ってから本番環境に進む**

- [ ] API Gatewayの動作確認

- [ ] エラーハンドリングの確認

#### 2.3 テスト環境確認完了条件
- ✅ すべての機能が正常に動作
- ✅ 本番環境と同等の動作
- ✅ パフォーマンスが問題ない
- ✅ セキュリティが確保されている

### 3. 本番環境デプロイフェーズ

#### 3.1 本番環境へのデプロイ
```bash
# バックエンド（Lambda）の本番環境デプロイ
serverless deploy --stage prod

# フロントエンドの本番環境デプロイ
cd study-tracker-frontend
npm run build
aws s3 sync dist/ s3://learninggarden.studio --delete
aws cloudfront create-invalidation --distribution-id E3RTAE75MJ0MSH --paths "/*"
```

## 🚨 重要なルール

### デプロイ前の必須確認事項

#### 1. ローカル開発完了確認
```bash
# バックエンドテスト
cd src
python -m pytest tests/

# フロントエンドテスト
cd study-tracker-frontend
npm run test
npm run build
```

#### 2. テスト環境での動作確認
**⚠️ 絶対にスキップしてはいけない手順**

```bash
# テスト環境での動作確認
curl https://[API-GATEWAY-DEV-URL]/health
curl https://[API-GATEWAY-DEV-URL]/api/v1/study-records

# ブラウザでの確認
# テスト環境のフロントエンドにアクセスして全機能を確認
```

#### 3. 段階的デプロイの原則
- **一度に全てを変更しない**
- **小さな変更から始める**
- **各段階で確認を取る**
- **問題があれば即座にロールバック**

### 禁止事項

#### ❌ やってはいけないこと
- **ローカル確認なしでのデプロイ**
- **テスト環境確認なしでの本番デプロイ**
- **大きな変更の一括デプロイ**
- **確認なしでの自動デプロイ**
- **エラーが発生している状態でのデプロイ**

#### ⚠️ 注意すべきこと
- **本番環境への直接的な変更**
- **設定ファイルの一括変更**
- **データベースの直接操作**
- **セキュリティ設定の変更**

## 🔧 トラブルシューティング

### よくある問題と解決方法

#### 1. デプロイエラー
```bash
# ログの確認
serverless logs -f api --tail

# ローカルでの再確認
# テスト環境での再確認
# 段階的な修正
```

#### 2. 動作確認エラー
```bash
# APIの動作確認
curl -X GET https://[API-URL]/health

# Lambda関数の直接確認
aws lambda invoke --function-name [FUNCTION-NAME] response.json

# CloudWatchログの確認
aws logs describe-log-groups
```

#### 3. フロントエンドエラー
```bash
# ビルドエラーの確認
npm run build

# 開発サーバーでの確認
npm run dev

# ブラウザの開発者ツールでの確認
```
